# Forecast site tags and layout sign-off

Forecast now starts with dive site name tags using the exact shared Explore filter component, including its selected state, typography, padding, border, and pill shape. Tags wrap for long names and narrow screens. A single selected site's panel is visible; inactive panels are hidden and inert. The carousel dots, duplicate slides, swipe navigation, and scroll snapping have been removed. Tags support click/tap, ordinary keyboard activation, and Arrow/Home/End navigation. Selection and the chosen day persist when returning from a site link. Previously loaded sites reuse the existing client cache.

The site heading and local clock have been removed. The three calendar tiles are centered above the forecast data card, outside its border. Wind speed and direction share one centered Wind heading; swell height and period share one centered Swell heading. Their respective table columns remain separate, retaining their existing values, grades, accessible descriptions, and site-chart links. Whole-second swell periods remain unchanged. The table still scrolls horizontally on phones so all stats are reachable. Swiping the stats never changes the selected site. The page navigation skeleton now shows site tags and dates above the data card.

Chromium review covered 320, 360, 390, 430, 768, 1024, and 1440 px widths plus 844 × 390 landscape. Inspected screenshots for desktop/mobile layout, long site names, both temperature and height unit settings, single featured site, multiple sites, unavailable/retry, delayed loading, and 125% text. No horizontal page overflow occurred. The date tile group is centered to within 1 px; the Wind and Swell headings are centered across their paired columns to within .01 px. The shared tags retain Explore's 9px/17px padding, 999px radius, 12.8px type, 600 font weight, and 44px minimum height. Keyboard site navigation, date changes without network requests, cached site switching, and browser Back passed. Mobile touch emulation scrolled the stats 302 px while keeping the selected site; tapping tags selected the requested site. No browser errors occurred. Touch testing used Chrome emulation, not a physical device.
